# PYTHON-EXPORT-RUNTIME-SURFACE-V1

Last updated: March 28, 2026

Status: Implemented

---

## Purpose

Define the first bounded runtime-surface refinement slice after the two-file Python export split shipped.

This contract is the implementation follow-on to:
- `PYTHON-EXPORT-V1-COMPLETE.md`
- `PYTHON-EXPORT-RUNTIME-LIBRARY-V1.md`
- `PYTHON-EXPORT-RUNTIME-LIBRARY-FOUNDATIONS-V1.md`

---

## Product Goal

Refine the exported Python surface so that:
1. `mcw_runtime.py` has a clearer stable public interface
2. generated workspace files have clearer provenance and dependency expectations
3. the two-file export reads more like a deliberate product surface and less like a direct artifact split

while preserving:
- parity
- current machine coverage
- helper-function execution structure
- stdlib-only exports

---

## Strategic Position

The runtime/library split is now real.

The next step is not broader coverage and not packaging/distribution work.

The next step is to make the exported Python surface more disciplined:
- clearer public vs internal runtime helpers
- clearer provenance and compatibility signaling
- cleaner generated workspace headers and import expectations

This is a product-surface slice, not a semantic expansion.

---

## Required V1 Shape

This slice must:
- preserve the current two-file artifact boundary
- preserve parity against current two-file export behavior
- preserve the current helper-function execution model
- define a stable public runtime surface inside `mcw_runtime.py`
- distinguish public runtime functions from internal-only helpers by naming and/or structure
- define the intended public runtime surface explicitly rather than auto-harvesting every helper
- expose the intended public runtime surface through `__all__`
- add explicit MCW provenance/version metadata to both emitted files
- make the generated workspace file’s dependency on `mcw_runtime.py` explicit and readable
- guard against a generated workspace filename colliding with `mcw_runtime.py`
- keep generated comments bounded and non-noisy

It must not:
- broaden machine coverage
- add packaging or installation requirements
- introduce a hidden interpreter layer
- redesign helper generation or top-level execution shape
- require ZIP bundling or delivery changes

---

## Artifact Shape

`mcw_runtime.py` should clearly separate:
- stable public runtime functions intended for workspace use
- internal validation/formatting helpers not meant to be treated as public machine-surface API
- an explicit `__all__` surface listing the intended public runtime names

`<workspace>.py` should clearly declare:
- that it was generated by MCW
- which runtime file it expects alongside it
- the runtime version it was generated against
- whether the workspace is stateless or ticked

The generated workspace should continue to use:
- `import mcw_runtime`
- qualified runtime references

---

## Runtime Surface Rule

V1 should treat the exported runtime surface as intentionally stable for generated workspace files from the same era of MCW export.

That means:
- public runtime function names should be deliberate and consistent
- internal helper naming should not be accidentally presented as public surface
- generated workspace code should rely only on the intended public runtime surface

This contract does not need to solve long-term cross-version compatibility.
It only needs to make the current surface explicit and disciplined.

---

## Parity Requirement

Parity must hold against the current shipped two-file export behavior:
- same sink output lines
- same ticked sink output lines
- same compatibility boundary
- same supported machine shapes

This slice must not change what exports successfully.

---

## Suggested V1 Scope

The first bounded runtime-surface slice should prove:
- one stateless exported workspace with clearer provenance and runtime dependency headers
- one temporal exported workspace with explicit ticked/runtime metadata
- one structured exported workspace still using qualified runtime references only

It does not need to prove:
- packaging
- ZIP download flow
- runtime distribution outside exported files
- a compact/minified export mode

---

## Success Condition

This slice is successful when:
- `mcw_runtime.py` exposes a visibly more deliberate public surface
- generated workspace files more clearly declare their provenance and runtime dependency
- two-file parity remains intact
- the exported Python feels more like a stable MCW product surface than a direct codegen split

---

## Outcome

Shipped in the first bounded runtime-surface refinement slice:
- `mcw_runtime.py` now declares a deliberate public surface through `__all__`
- generated workspace files now declare runtime dependency, runtime version, workspace name, and execution mode
- generated split-export filenames now avoid collisions with `mcw_runtime.py`
- two-file parity remains intact without broadening machine coverage
